Kookie Flow supports grouping nodes together, adding annotations, and creating edge waypoints for cleaner graph layouts.

## Node Groups

Groups are container nodes that can hold other nodes as children. When a group is collapsed, all its children are hidden.

### Creating a Group

```tsx
import type { Node } from '@kushagradhawan/kookie-flow';

const nodes: Node[] = [
  // Group node (container)
  {
    id: 'group-1',
    type: 'group',
    position: { x: 0, y: 0 },
    data: { label: 'Processing Pipeline' },
    width: 400,
    height: 300,
    collapsed: false, // Set to true to hide children
  },
  // Child nodes (reference parent via parentId)
  {
    id: 'node-1',
    type: 'default',
    parentId: 'group-1',
    position: { x: 20, y: 50 }, // Position relative to parent
    data: { label: 'Input' },
  },
  {
    id: 'node-2',
    type: 'default',
    parentId: 'group-1',
    position: { x: 20, y: 150 },
    data: { label: 'Output' },
  },
];
```

### Collapsing Groups

Toggle the `collapsed` property to show/hide child nodes:

```tsx
function handleToggleCollapse(groupId: string) {
  setNodes(nodes.map(node =>
    node.id === groupId
      ? { ...node, collapsed: !node.collapsed }
      : node
  ));
}
```

When collapsed:
- All descendant nodes are hidden from the viewport
- Edges connected to hidden nodes remain visible (connected to the group boundary)
- The group displays a collapse indicator

### Group Properties

| Property | Type | Description |
|----------|------|-------------|
| `type` | `'group'` | Identifies the node as a group |
| `collapsed` | `boolean` | Whether children are hidden |
| `parentId` | `string` | Parent group ID (for nested groups) |
| `extent` | `'auto' \| 'fixed'` | How group bounds are calculated |

### Nested Groups

Groups can be nested inside other groups:

```tsx
const nodes = [
  { id: 'outer', type: 'group', data: { label: 'Outer' } },
  { id: 'inner', type: 'group', parentId: 'outer', data: { label: 'Inner' } },
  { id: 'node', parentId: 'inner', data: { label: 'Deeply Nested' } },
];
```

## Comments

Comment nodes are sticky notes for adding annotations to your graph. They render as DOM elements with customizable styling.

### Creating Comments

```tsx
const comment: Node = {
  id: 'comment-1',
  type: 'comment',
  position: { x: 500, y: 100 },
  width: 200,
  height: 100,
  data: {
    content: 'This section handles user authentication.\n\nRemember to validate tokens!',
    backgroundColor: '#FFF9C4', // Light yellow (default)
    textColor: '#424242',       // Dark gray (default)
    fontSize: 14,               // Default: 14
  },
};
```

### Comment Styling

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `content` | `string` | - | Text content (supports line breaks) |
| `backgroundColor` | `string` | `#FFF9C4` | Background color |
| `textColor` | `string` | `#424242` | Text color |
| `fontSize` | `number` | `14` | Font size in pixels |

### Color Presets

Common sticky note colors:

```tsx
const colors = {
  yellow: '#FFF9C4',
  blue: '#BBDEFB',
  green: '#C8E6C9',
  pink: '#F8BBD9',
  orange: '#FFE0B2',
  purple: '#E1BEE7',

```

## Reroute Nodes

Reroute nodes are edge waypoints that help organize complex graphs. They appear as small circles that edges can pass through.

### Creating Reroutes

```tsx
const reroute: Node = {
  id: 'reroute-1',
  type: 'reroute',
  position: { x: 200, y: 150 },
  data: {},
};

// Connect edges through the reroute
const edges = [
  { id: 'e1', source: 'node-1', target: 'reroute-1' },
  { id: 'e2', source: 'reroute-1', target: 'node-2' },
];
```

### Reroute Behavior

- Rendered as small WebGL circles (instanced for performance)
- Can be selected and dragged like regular nodes
- Act as connection points for edges
- Useful for routing edges around obstacles

### Visual Style

Reroutes display as:
- Small circle (8px radius)
- Cross pattern inside when not selected
- Highlight ring when selected
- Match the theme's accent color

## Store Actions

The Zustand store provides actions for managing groups:

```tsx
import { useFlowStoreApi } from '@kushagradhawan/kookie-flow';

function GroupControls() {
  const store = useFlowStoreApi();

  return (
    <>
      <button onClick={() => store.getState().toggleGroupCollapse('group-1')}>
        Toggle Collapse
      </button>
      <button onClick={() => store.getState().expandGroup('group-1')}>
        Expand
      </button>
      <button onClick={() => store.getState().collapseGroup('group-1')}>
        Collapse
      </button>
    </>
  );
}
```

### Available Actions

| Action | Description |
|--------|-------------|
| `getGroupChildren(groupId)` | Get direct children of a group |
| `getGroupDescendants(groupId)` | Get all descendants (recursive) |
| `toggleGroupCollapse(groupId)` | Toggle collapsed state |
| `expandGroup(groupId)` | Expand a collapsed group |
| `collapseGroup(groupId)` | Collapse an expanded group |
| `isGroupCollapsed(groupId)` | Check if group is collapsed |
| `getGroupBounds(groupId)` | Get bounding box of group contents |
| `setNodeParent(nodeId, parentId)` | Set/change a node's parent |
| `moveGroup(groupId, delta)` | Move group and all descendants |

## Node Changes

Handle grouping-related changes through `onNodesChange`:

```tsx
import type { NodeChange } from '@kushagradhawan/kookie-flow';

function handleNodesChange(changes: NodeChange[]) {
  for (const change of changes) {
    switch (change.type) {
      case 'collapse':
        // Group collapsed/expanded: change.id, change.collapsed
        console.log(`Group ${change.id} collapsed: ${change.collapsed}`);
        break;
      case 'parent':
        // Node reparented: change.id, change.parentId
        console.log(`Node ${change.id} new parent: ${change.parentId}`);
        break;
    }
  }
}
```

## Performance

Grouping features are optimized for large graphs:

- **O(1) visibility checks**: Hidden nodes are pre-computed into a Set
- **Efficient collapse**: Only rebuilds when collapse state changes
- **Instanced rendering**: Reroute nodes use WebGL instancing
- **Frustum culling**: Hidden and off-screen nodes skip rendering
