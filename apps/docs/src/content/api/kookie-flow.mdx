`KookieFlow` is the component that draws a graph. It renders a WebGL canvas that fills its parent
element, with a layer of HTML over the canvas for overlays of your own. The tables below list
every prop it takes, with its type and default, and link each one to the chapter that explains it.

## Render the graph

```tsx title="editor.tsx"
'use client';

import { useRef } from 'react';
import { KookieFlow, useGraph, type KookieFlowInstance } from '@kushagradhawan/kookie-flow';

export function Editor() {
  const flowRef = useRef<KookieFlowInstance>(null);
  const { entities, edges, onEntitiesChange, onEdgesChange, onConnect } = useGraph();

  return (
    <div style={{ height: 600 }}>
      <KookieFlow
        ref={flowRef}
        entities={entities}
        edges={edges}
        onEntitiesChange={onEntitiesChange}
        onEdgesChange={onEdgesChange}
        onConnect={onConnect}
      />
    </div>
  );
}
```

`KookieFlow` is 100% of its parent's width and height, so give the parent a height. With no height,
the canvas is zero pixels tall and nothing shows.

The package carries no `'use client'` directive, so in a Next.js App Router app, render `KookieFlow`
from a file that starts with `'use client'`. The `ref` gives you the methods listed in [The ref instance](/api/instance).

## Props

Only `entities` and `edges` are required. A default of "none" means the prop is `undefined` unless
you set it.

## Render overlays as children

Anything you pass as `children` renders in a layer of HTML that covers the canvas exactly. Use it
for controls that belong to the graph: a zoom readout, a legend, or the [`Toolbar`](/interaction/toolbar)
and [`Minimap`](/styling/minimap) components.

Children render inside the flow, so the hooks that need a flow work there. `useFlowStoreApi`,
`useFlowStore`, `useClipboard`, `Toolbar` and `Minimap` throw anywhere else. The [Hooks](/api/hooks) chapter
lists which hooks need a flow and which don't.

This button shows the zoom level and resets the view when clicked:

```tsx title="zoom-button.tsx"
'use client';

import { useEffect, useRef } from 'react';
import { useFlowStoreApi } from '@kushagradhawan/kookie-flow';

export function ZoomButton() {
  const store = useFlowStoreApi();
  const label = useRef<HTMLSpanElement>(null);

  useEffect(() => {
    let frame = 0;
    const write = () => {
      frame = 0;
      const percent = Math.round(store.getState().viewport.zoom * 100);
      if (label.current) label.current.textContent = `${percent}%`;
    };
    write();
    const unsubscribe = store.subscribe(
      (state) => state.viewport.zoom,
      () => {
        if (frame === 0) frame = requestAnimationFrame(write);
      }
    );
    return () => {
      unsubscribe();
      cancelAnimationFrame(frame);
    };
  }, [store]);

  return (
    <button
      type="button"
      style={{ position: 'absolute', top: 12, right: 12, pointerEvents: 'auto' }}
      onPointerDown={(event) => event.stopPropagation()}
      onClick={() => store.getState().setViewport({ x: 0, y: 0, zoom: 1 })}
    >
      <span ref={label} />
    </button>
  );
}
```

```tsx
<KookieFlow entities={entities} edges={edges} onEntitiesChange={onEntitiesChange}>
  <ZoomButton />
</KookieFlow>
```

The button writes the zoom into its label through a ref, at most once a frame, instead of keeping
it in React state. Zooming changes the value on every wheel event, and a React render for each one
would slow the canvas down.

Follow these rules for anything you render as a child:

- **Set `pointerEvents: 'auto'` on what people click.** The overlay layer has
  `pointer-events: none`, so the canvas under it keeps working. Your children inherit that value
  until they set their own.
- **Stop `onPointerDown` from reaching the canvas.** A press on a child also reaches the canvas,
  which takes focus and can select, drag or deselect whatever lies under the pointer. The library's
  own toolbar stops the event the same way.
- **Position in canvas pixels.** The layer's top-left corner is the canvas's top-left corner. To
  follow a point on the graph, convert it with `worldToScreen` and update the element through a
  ref. [Hooks](/api/hooks#style-and-layout-hooks) has an example that follows a socket.
- **Put a large panel outside `KookieFlow`.** The wheel over a child zooms the canvas, so a
  scrolling list inside the layer doesn't scroll. Screen readers such as NVDA and JAWS also treat
  the whole canvas, children included, as one application, and leave their reading mode inside it.
  A panel positioned over the canvas from outside avoids both. This is a judgment, not a measured
  limit.

Typing into an input inside a child doesn't trigger the canvas's keyboard shortcuts. The canvas
answers keys only while the canvas itself has focus. The exception is `useGraph` with `history` on:
its undo and redo keys work while focus is anywhere inside `KookieFlow`, so Cmd+Z or Ctrl+Z in that
input undoes the graph rather than your typing.

## Keep props stable between renders

Some props are compared by identity. When your component renders again and passes a new object
or array, `KookieFlow` redoes work even if the contents are the same.

| Prop | What a new object or array costs |
| --- | --- |
| `entities`, `edges` | The canvas replaces its copy of the graph and rebuilds its lookups. Pass a new array only when the graph changed, which `useGraph` does for you. |
| `socketTypes` | Every edge is synced again, and the canvas rebuilds its buffers for edges, sockets and widgets. |
| `entityTypes` | The table is compared entry by entry. A new object holding the same entry objects resolves nothing again, but new entry objects make every entity resolve again. |
| `font` | A custom `FontConfig` with the same name and atlas URLs isn't loaded again, but a new object still re-renders every component inside the flow that reads the font. |
| `widgetTypes`, `ThemeComponent` | A component defined inside your render function is a new component each time, so React remounts every widget that uses it. |

Define these outside your component, or wrap them in `useMemo`:

```tsx title="editor.tsx"
'use client';

import { KookieFlow, useGraph, type SocketType } from '@kushagradhawan/kookie-flow';

// Module scope: one object for the life of the app, however often Editor renders.
const socketTypes: Record<string, SocketType> = {
  audio: { name: 'Audio', color: '--cyan-10' },
  prompt: { name: 'Prompt', color: '--amber-10', widget: 'textarea' },
};

export function Editor() {
  const { entities, edges, onEntitiesChange, onEdgesChange, onConnect } = useGraph();

  return (
    <div style={{ height: 600 }}>
      <KookieFlow
        entities={entities}
        edges={edges}
        onEntitiesChange={onEntitiesChange}
        onEdgesChange={onEdgesChange}
        onConnect={onConnect}
        socketTypes={socketTypes}
      />
    </div>
  );
}
```

`entityStyle` is compared by value, so an inline object is fine. `penStyle` is read when the pen
draws, `minimapProps` is spread into the minimap, and `defaultViewport` is read once, so all three
can be written inline too. A `minimapProps.entityColor` function is the exception, which
the [Minimap](/styling/minimap#read-colours-from-the-theme) chapter explains.

## Show performance stats

Set `showStats` to show a frame-rate panel while you work on a graph's performance:

```tsx
<KookieFlow entities={entities} edges={edges} showStats={process.env.NODE_ENV === 'development'} />
```

The panel is fixed to the top-left corner of the page, not of the canvas, and sits above the rest
of the page. Click it to switch between its readings:

- **FPS**: frames drawn per second.
- **MS**: how long the canvas took to draw the last frame, in milliseconds. React renders and your
  HTML overlays aren't included.
- **MB**: memory used by JavaScript. Only browsers that report memory, such as Chrome, show this
  reading.

The canvas draws every frame, even when nothing moves, so FPS stays near the display's refresh
rate while a graph is idle. Watch it while you pan, zoom and drag to see where a large graph slows
down.

## Recover from a canvas crash

`KookieFlow` wraps its WebGL canvas in `CanvasErrorBoundary`. When a component inside the canvas
throws, the boundary replaces the canvas with the message "Something went wrong rendering the
canvas." and a **Retry** button, and logs the error to the console with the prefix
`[KookieFlow] Canvas crashed:`.

Only the canvas is replaced. Your children and the minimap stay on screen, and the flow keeps its
copy of the graph, so **Retry** mounts a new canvas that draws the same graph. Until then,
`toImage()` returns `null`.

An error inside the canvas stops at that boundary, so an error boundary of yours around
`KookieFlow` never receives it. Yours still receives errors thrown anywhere else in the flow,
including in your children, and those unmount the whole flow.

`CanvasErrorBoundary` is exported for WebGL canvases of your own. It takes `children` and an
optional `onError(error, errorInfo)`, which is where you report the crash. Its fallback fills the
nearest positioned ancestor, so give the wrapper a position:

```tsx title="model-preview.tsx"
'use client';

import { Canvas } from '@react-three/fiber';
import { CanvasErrorBoundary } from '@kushagradhawan/kookie-flow';

export function ModelPreview({ onCrash }: { onCrash: (error: Error) => void }) {
  return (
    <div style={{ position: 'relative', height: 240 }}>
      <CanvasErrorBoundary onError={(error) => onCrash(error)}>
        <Canvas>
          <mesh>
            <boxGeometry />
            <meshNormalMaterial />
          </mesh>
        </Canvas>
      </CanvasErrorBoundary>
    </div>
  );
}
```
